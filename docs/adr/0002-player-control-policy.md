# ADR-0002：先集中播放器控制协议策略

## 状态

Accepted · 2026-11-17

## 背景

用户选择优先重构播放器控制与 IPC。现有传输已经具备长度限制、碎片读取、取消与超时测试。
运行目录参数不会改变全局命名管道，这属于当前实际行为；多实例语义尚未定义。

## 决策

先将端点、默认超时和响应解释从通用 lib 移入 player_control module。
保留原 command 调用路径的重导出，减少调用方迁移风险。
传输机制不变，通过内部 transport seam 验证成功、拒绝、连接失败及 deadline 传递。
本步仅建立协议策略拥有者；类型化业务操作及多实例身份留待后续实现。

## 替代方案与后果

直接为每个 root 生成管道名会要求同时修改播放器、启动和管理员交接，不适合作为第一步。
整体替换 IPC transport 会丢失已有验证收益，当前没有测量证据支持。
本步行为保持，仍使用全局端点，不能宣称已实现多实例隔离。
